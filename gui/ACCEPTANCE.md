### Бэкенд-шов: сколько стоит страница лога

Панель — CLI-first, страница лога это argv, который собирает `engine::log::page`.
Замерено напрямую на том же репозитории (3 прогона, мс):

| Запрос | Прогоны | Медиана |
|--------|---------|---------|
| `git log --format=… --max-count=200 --date-order --exclude=refs/stash --exclude=refs/notes/* --all` | 75 / 73 / 73 | **73 мс** |
| то же с `--skip=9800` | 72 / 73 / 72 | 72 мс |
| то же с `--skip=19800` | 74 / 73 / 73 | 73 мс |
| обход всех 20 000 строк (`--max-count=20000`) | 94 / 94 / 93 | 94 мс |
| запрос вершины (`--max-count=1 --format=%H`) | 72 / 73 / 73 | 73 мс |

Вывод: **глубина страницы на стоимость не влияет** — `--skip=19800` стоит столько же,
сколько `--skip=0`; страница целиком упирается в постоянную стоимость запуска `git`
с `--all`. Первая страница = три запуска `git` ≈ 0.22 с из измеренных 0.63 с.

В `bigrepo/.git/changelists.json` записан стор в форме, которую пишет TUI (`Default` +

То есть работа в режиме Log changelist'ы не трогает и формат остаётся общим.

## Находки живого прогона (prd_02, задача 13)

**F1. Старт в режиме Log падает в error boundary.** Если прошлый сеанс закончился в
режиме Log (режим лежит в `localStorage`), следующий запуск показывает не панель, а
«Something went wrong in the UI / Unknown error» с кнопками «Reload state» /
«Reload window». Воспроизведено 5 раз, на репозитории в 22 224 коммита **и на
репозитории из одного коммита**, с автоматизацией и без неё. Кнопка «Reload state»
восстанавливает панель Log полностью, то есть данные целы — ломается именно первый
монтаж. Указатель для починки: `App.tsx` вызывает `openInitial()` внутри `onMount`,
то есть **после** первого рендера, а `LogView` на первом же рендере дергает
`ensureLoaded()` → `log_page`, когда репозиторий бэкенду ещё не открыт.
Это дефект пути «по умолчанию» для всякого, кто пользуется панелью.

**F2. Прокрутка вглубь лога выносит бюджет памяти в ~2.6 раза.** Из чистого состояния
Log (231–233 МБ) клавиатурная прокрутка списка коммитов (End / Down) поднимает RSS до
плато в районе **570–670 МБ**. Три независимых наблюдения, протоколы не совпадали
(800 нажатий End — 569 МБ; 320 нажатий из чистого старта — 641 МБ; смешанная серия
End/Down — 668 МБ), медиана **641 МБ**. При этом шапка списка остаётся в состоянии
«Loading history…», курсор не уходит с самого свежего коммита, а сообщение о потолке
20 000 строк так и не появляется.

Контрольный опыт (чтобы отделить приложение от инструмента замера): в **том же**
режиме Log с загруженной страницей — 20 полных обходов AX-дерева **без единого
нажатия**: 231 → 231 МБ, роста нет. Значит рост даёт ввод, а не снятие состояния.

Что именно ломается — доставка клавиши до панели или ведение курсора — под
синтезированным вводом System Events развести не удалось; вклад одного нажатия
измерить тоже не вышло (базовая линия одиночного опыта была загрязнена монтажом
панели). Обе ветки требуют отдельной задачи.

**F5. Неотслеживаемый файл вымывается из changelist'а.** Если в
`.git/changelists.json` записан путь, которого git не отслеживает, GUI при первом же
синке переписывает файл и **выкидывает этот путь** из списка (сам список остаётся).
Наблюдалось на `config-local.xml`, пока он был untracked; после `git add` + коммита
тот же путь сохраняется. Против TUI поведение **не сравнивалось**, поэтому здесь оно
не объявляется дефектом — но потеря записи молчаливая, и разойтись с TUI тут легко.

**F3. Формат даты в одном окне разный.** В таблице лога дата выводится как
`15.09.2020` (ru), в панели деталей того же коммита — `9/15/2020, 10:39:28 AM` (en-US).

**F4. Потолок в 20 000 строк ни разу не был достигнут** — из-за F2 до него не доходит
ни прокрутка, ни клавиатура; текст «Показаны первые 20 000 коммитов — уточните фильтр»
живьём не показывался.

Заодно подтверждено живьём (панель деталей на реальном коммите): полный 40-символьный
хэш, автор с почтой, «In 1 branch: main», «CHANGED FILES · 1 FILE», длинное тело
сообщения выводится целиком и не обрезается; дерево веток сворачивает `feat/*` в узел.

## Известные упрощения MVP (в следующие PRD)

- Токен-подсветка синтаксиса в diff — сейчас раскраска diff-строк; token-highlight позже.
- Прогресс долгих операций — busy-бар (не потоковый прогресс push/pull).
- Частичный коммит только застейдженных hunk'ов — коммит берёт полное содержимое
  выбранных файлов (hunk-staging живёт в индексе, но commit_list коммитит файлы целиком).
- Rename в коммите: стейджится новый путь; удаление старого — общий случай, не спец-обработка.
- Picker "открыть репозиторий" — сейчас открывается репо текущего каталога.
- Стор пишется в `<repo_root>/.git/changelists.json` (буквально, как в TUI — для
  byte-compat). В **git-worktree/submodule** `.git` — файл, а не каталог, поэтому этот
  путь там не разрешится; отдельные worktree-репозитории в MVP не поддержаны (общий с
  TUI лимит; при снятии — резолвить через `git rev-parse --git-dir` в обоих инструментах).
- **hunk-staging и коммит не связаны:** `apply_patch --cached` стейджит hunk в индекс,
  но `commit_paths` затем делает `git add -- <files>` и коммитит **полное** содержимое
  выбранных файлов — частичный hunk-стейдж коммитом не сохраняется (см. выше).
